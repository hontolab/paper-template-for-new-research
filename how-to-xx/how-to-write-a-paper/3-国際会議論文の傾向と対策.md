# 国際会議論文の傾向と対策：CHI・CSCW・UIST・IUI・CHIIR・SIGIR

[1-学術論文の書き方.md](1-学術論文の書き方.md)と[2-文書の書き方.md](2-文書の書き方.md)で述べた原則は，これらの会議すべてに通用します．しかし，各会議には固有の期待と評価文化があります．なお投稿規定（ページ数，匿名化，テンプレート）は年々変わるため，**投稿前に必ず最新のCall for Papers / Author Guideを確認してください**．

## 1. SIGCHI系（CHI / CSCW / UIST / IUI）に共通する事項

- **貢献タイプの自覚**：HCIの貢献は，Wobbrock & Kientzの分類（empirical / artifact / methodological / theoretical / dataset / survey / opinion）が広く参照されます．自分の論文が主にどのタイプの貢献なのかをイントロで明確にし，そのタイプに応じた評価を設計しましょう（例：artifact貢献なら新規性と実現可能性，empirical貢献なら知見の妥当性）
- **匿名投稿と査読プロセス**：匿名化（自己引用の書き方に注意）と，AC（Associate Chair）による取りまとめ，リバッタル（著者反論）期間があります．リバッタルで答えやすいよう，主張と根拠の対応を本文で明確にしておきましょう
- **研究倫理の明記**：ユーザを対象とする研究では，倫理審査（IRB等）の承認，参加者への説明と同意，謝礼，データの匿名化・管理方法をMethodセクションに書きます
- **ユーザスタディ報告の型**：参加者（人数・属性・リクルート方法），タスク，手続き，収集データ，分析方法を，再現可能なレベルで記述します
- **定性分析の厳密さ**：thematic analysisやgrounded theoryなど，手法名と手順を明記します．複数コーダーによるコーディングと一致度，または単独コーディングの正当化を示し，参加者の発話引用で主張を裏付けます
- **定量分析の透明性**：p値だけでなく効果量・信頼区間を報告し，検定の前提（正規性など）を確認します．SIGCHIコミュニティは近年，統計報告の透明性への要求が高くなっています
- **図の重要性**：1ページ目のティーザー図（システムや知見を一目で伝える図）が，第一印象を大きく左右します

## 2. 会議ごとの特徴

- **CHI**：聴衆が非常に広いため，イントロで「HCIコミュニティ全体にとってなぜ重要か」を明示する必要があります．Discussionでのdesign implications（デザインへの示唆）が定番の型です．貢献がnicheに見えると "not of broad interest" と評されやすいので，framingを一段広く取りましょう
- **CSCW**：協調作業・ソーシャルコンピューティングの会議です．社会技術的（sociotechnical）なframingと，理論（articulation work，boundary objectsなど）への接続が評価されます．フィールドワークやインタビューによる定性研究の「厚い記述」が強みになります．PACM HCI形式で方法・考察を十分な分量で書けます（ただし冗長は不可です）
- **UIST**：新規インタラクション技術・システムの会議です．技術的新規性（何が初めて可能になったか）と技術評価（精度・性能・技術的ベースラインとの比較）が中心となります．**ビデオフィギュアが実質必須**で，採否への影響が大きいです．大規模ユーザスタディよりも，技術の実現可能性と有効性を的確に示す評価が求められます．なお，提案システムの利用シナリオを一つ決めて論文全体を貫くのは，running example（[1-学術論文の書き方.md](1-学術論文の書き方.md) 3.4節）のUIST的な応用と言えます
- **IUI**：知的ユーザインタフェース（HCIとAI・機械学習の交差点）の会議です．推薦・適応型UI・説明可能AI・LLMベースのインタラクションなど，「知的に振る舞うインタフェース」が対象となります．貢献は**AI技術の新規性とインタラクション設計の両輪**で評価されるため，評価もアルゴリズム性能（オフライン評価・アブレーション）とユーザスタディの両方が期待されることが多いです．査読者にHCI系とAI系が混在するので，AI部分の技術的詳細とユーザ視点での意義の**双方を過不足なく書きましょう**（どちらか一方の読者にしか通じない書き方は避けます）
- **CHIIR**：インタラクティブ情報検索（IIR）の会議です．検索という文脈でのユーザ中心研究であり，HCI系とIR系双方の査読者を意識する必要があります．検索タスクの設計，検索行動ログ（クエリ，クリック，滞在時間）と主観指標（アンケート，NASA-TLX，UESなど）の組み合わせ，タスク・トピックの統制（ラテン方格など）を丁寧に報告しましょう
- **SIGIR**：IRのトップ会議で，**実証的厳密さが最重要**です．標準テストコレクション（TREC系など）や広く使われる公開データセットでの評価，強いベースライン（古典手法＋最新手法）との比較，標準的な評価指標（nDCG，MAP，MRR，Recallなど），統計的有意差検定，アブレーションスタディ，再現性（コード・設定の公開）が求められます．ベースライン選定の妥当性は，Related Workで正当化しておきましょう

## 3. 一般原則との関係

[1-学術論文の書き方.md](1-学術論文の書き方.md)と[2-文書の書き方.md](2-文書の書き方.md)の一般原則（イントロの型，running example，Related Workのグループ化と差分明示，RQ駆動の評価，パラグラフライティング）は，これらの会議でもそのまま通用します．その上で，SIGCHI系では「ユーザ研究の報告の厳密さ・倫理・貢献タイプの明確化」，IUIではさらに「AI技術面の評価」，SIGIR/CHIIRでは「ベンチマーク・ベースライン・統計検定による実証的厳密さ」という会議固有の期待を上乗せする，と考えるとよいでしょう．

## 4. 参考サイト・資料

- **Wobbrock & Kientz, "Research Contributions in Human-Computer Interaction" (ACM Interactions, 2016)**
  HCI研究の貢献タイプ7分類を解説した論文です．CHI/CSCW/UIST/IUI投稿時の貢献のframingに有用です（→1章）．
- **投稿先の会議・ジャーナルの採録論文を3〜5本精読する**
  最良の教材です．章立て，Related Workの位置，Evaluationの粒度など，その分野の「暗黙の型」が一番よくわかります．
- **各会議のCall for Papers / Author Guide**
  ページ数，匿名化の要否，テンプレート，付随資料（ビデオ等）の規定は年ごとに変わるため，投稿のたびに最新版を確認してください．
