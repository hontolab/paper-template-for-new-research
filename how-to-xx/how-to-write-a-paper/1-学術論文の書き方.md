# コンピュータサイエンス分野における学術論文の書き方

この資料は，主にSimon Peyton Jones *How to Write a Great Research Paper*，Jennifer Widom *Tips for Writing Technical Papers*，および『エリート的な文章の書き方』の内容を統合し，計算機科学（Computer Science; CS）分野の論文の標準的な書き方をまとめたものです．

本ガイドは3部構成です．本書（第1部）では，論文の構成と各章の中身を扱います．段落・文レベルの書き方は[2-文書の書き方.md](2-文書の書き方.md)を，投稿先会議ごとの傾向は[3-国際会議論文の傾向と対策.md](3-国際会議論文の傾向と対策.md)を参照してください．

## 1. 全体の心構え：論文は「アイデアを読者の頭に移植する」もの

Peyton Jonesによれば，論文の目的は**あなたのアイデアを読者の頭に伝えること**であり，論文中のすべてがこの一点に奉仕すべきだとされています．また彼は，「研究してから書く」のではなく**「書きながら研究する」**ことで思考が明確になり，理解していない部分が浮き彫りになるとも述べています．つまり執筆は研究報告の手段ではなく，研究そのものの一部なのです．

もう一つ重要なのは，査読者や読者は「アブストラクト → 図 → 結論 →（気になれば）本文」という順で流し読みすることが多いという現実です．どの粒度で読んでも主張が伝わる構造（タイトルだけ，アブストラクトだけ，イントロだけ，でもそれぞれ完結して伝わる）を目指しましょう．

## 2. 標準的な章立て

CSの実証系・システム系論文の典型構成は次の通りです（分野により多少変わります）．

1. Title / Abstract
2. Introduction（序論）
3. Related Work（関連研究）※末尾に置く流儀もあります（→4.4節）
4. Running Example（一貫した実行例）※独立章にする場合（→3.4節）
5. Proposed Method / System Design（提案手法）
6. Implementation（実装）※システム系の場合
7. Evaluation / Experiments（評価・実験）
8. Discussion / Limitations（考察・限界）
9. Conclusion / Future Work（結論・今後の課題）

## 3. 各章に書くべき内容

### 3.1 タイトル

Widomによれば，タイトルには複数の戦略があります．

- **長く説明的**：*Linear-Time External Multipass Sorting with Approximation Guarantees*
- **短く簡潔**：*Approximate External Sort*
- **中間の長さ＋覚えやすいシステム名**：*Floosh: A Linear-Time Algorithm for Approximate External Sort*

覚えやすい名前は，読者・査読者の記憶に残りやすくなります．

### 3.2 Abstract

論文全体のミニチュアです．Widomは「問題・アプローチと解・主要な貢献を述べ，**背景や動機はほとんど入れない**．事実に基づき，かつ網羅的に」と指導しています．構成としては以下が定番です．

- 背景（0〜1文）
- 問題（1文）
- 既存手法の限界（1文）
- 提案（1〜2文）
- 結果（1〜2文）

数値的な成果（「従来比◯%改善」など）を具体的に入れると強くなります．また，Abstractの文を本文で一語一句そのまま使い回さないようにしましょう（Widom）．

### 3.3 Introduction

論文の勝負所です．Widomは「**査読者はイントロを読み終えた時点で採否の初期判断をほぼ下し，残りの部分はその判断を裏付ける証拠を探しながら読む**」と指摘しています．

構成は，Stanford InfoLab流の「5つの問いに答える5段落」が最も明快な型です．

1. **What is the problem?** — 問題は何か
2. **Why is it interesting and important?** — なぜ興味深く重要か（この分野で何が重要か，なぜ今解くべきか）
3. **Why is it hard?** — なぜ難しいか（素朴なアプローチはなぜ失敗するか＝自明でないことを示す）
4. **Why hasn't it been solved before?** — なぜ未解決だったか（既存アプローチのギャップ．何が足りず，自分の方法はどう違うか）
5. **What are the key components of my approach and results?** — アプローチと結果の鍵は何か（＋限界も明記）

そして最後に **"Summary of Contributions"** を置きます．

- 貢献は箇条書きで「本論文の貢献は次の3点である」と明示しましょう
- Peyton Jones：貢献は**検証可能（refutable）な主張**として書きます
- Widom：各貢献に**対応するセクション番号**を付けます．これによりイントロ自体が論文全体のアウトラインを兼ね，「2章で背景を述べ，3章で手法を述べ…」という中身のない章構成の羅列（roadmap paragraph）が不要になります

### 3.4 提案手法・本文（Body）

#### ★ Running Example：一貫した具体例を論文全体で使う

本文の書き方で最も推奨したい技法が，Widomの **Running Example** です．

> **可能であれば，一つの具体例（running example）を論文全体を通して使うこと．** 導入位置は，イントロ末尾の小節とするか，（Related Workの位置に応じて）独立した2章または3章とする．（Widom）

これはPeyton Jonesの「いきなり一般化・形式化から入らず，まず具体例で直感を与えてから一般化する（examples first）」をさらに一歩進めた流儀で，**例を場面ごとに使い捨てるのではなく，一つの例を論文全体で成長させる**点が特徴です．利点は次の通りです．

- 読者は新しい概念が出てくるたびに新しい状況を理解し直す必要がなく，「さっきの例だとこうなる」と**認知負荷を抑えながら**読み進められます
- 定義 → アルゴリズム → 実行例 → 実験と，**同じ例が一本の糸として論文を貫く**ため，各章のつながりが自然に生まれます
- 例を先に固定することで，著者自身も手法の説明の抜け漏れに気づきやすくなります

Widom自身，執筆ガイドの中で「外部マルチパスマージソートの新アルゴリズム」という架空の例を冒頭で導入し，タイトル・アブストラクト・イントロの書き方をすべてこの例に沿って説明してみせています．つまりガイドそのものがrunning exampleの実演になっているのです．

#### 本文の2大ガイドライン（Widom）

1. **3ページ目（全体の約1/4）までに，明確な新規技術貢献を提示しましょう**
2. **各セクションはストーリーを語ります**．ただし「結果に至った試行錯誤の経緯」ではなく「**結果そのものの物語**」を，中断なく線形に語ります（読者の流れを妨げる細部はAppendixへ）

#### その他の指針

- **Preliminaries**：新規でない前提知識（記法・用語）を切り分けて簡潔に書きます．「どこからが自分の貢献か」の境界を明確にする役割を持ちます
- **トップダウン記述**：読者が「この先どこへ向かうのか」を常に見通せるように書きます．読み飛ばしても概要が掴めるのが理想です
- 読者が再現できる程度の詳細さと，本質を見失わない抽象度のバランスを取りましょう
- 設計上の選択（design decision）には，必ず「なぜそうしたか」の理由を添えましょう

### 3.5 Evaluation / Experiments

まず「何を検証したいのか」を**Research Question（RQ1, RQ2, …）や仮説として明示**し，それに対応する実験を設計します．Widomの整理を借りると，実験設計では次の2つを意識するとよいでしょう．

- **何を測るか**：実行時間，重要パラメータへの感度，スケーラビリティ（データサイズ・問題の複雑さ）など
- **何を示すか**：絶対性能（実用に足るか），素朴な手法との比較，既存手法との比較，提案手法間の比較

その上で，報告の際は以下を守りましょう．

- 実験設定（データセット，ベースライン，指標，ハイパーパラメータ，環境）を**再現可能なレベル**で書きます
- 結果は「事実の記述」と「解釈」を区別して述べます
- 都合の悪い結果も隠さず，Limitationsで誠実に議論する方が査読では好印象です．Widomも「自分の手法を良く見せるためだけの意味のない実験（hokey experiments）」に陥る論文が多いと警告しています
- ユーザスタディ系なら，統計的検定や参加者数の妥当性も必要です（→[3-国際会議論文の傾向と対策.md](3-国際会議論文の傾向と対策.md)）

### 3.6 Conclusion / Future Work

- **AbstractやIntroductionの繰り返しは厳禁です**（Widom）．「何がわかったか」を簡潔に述べ，可能なら定量結果を使って当初の主張をより具体的に述べ直します（例：イントロで「大幅に高速化」と述べたことを「◯倍の高速化を確認した」と具体化する）
- 新しい主張をここで初めて出してはいけません
- **Future Work**は研究の価値の一部です．進行中の研究があれば「現在〜に取り組んでおり，予備的結果は有望である」と明記して，縄張りを示しましょう（Widom）

### 3.7 謝辞・参考文献・Appendix（Widom）

- **謝辞**：議論・草稿へのフィードバック・実装などで貢献した人は，迷ったら入れましょう（漏らすと角が立ちます）
- **参考文献**：Webから拾ったBibTeXをコピペで済ませず，全エントリの完全性・一貫性を最後に必ず確認しましょう
- **Appendix**の原則：(1) 貢献の理解に必要な内容は入れません (2) 大多数の読者が興味を持たない詳細（証明・アルゴリズムの細部）はすべて入れます．本文のストーリーを中断させる材料の退避先と考えましょう

## 4. 関連研究（Related Work）の書き方

初心者が最も失敗しやすい章です．

### 4.1 論文リストの羅列にしない

「Aは〜した．Bは〜した．Cは〜した」と並べるだけでは意味がありません．関連研究の役割は，**先行研究の地図の中に自分の研究を位置づけ，「既存研究では埋まっていない穴があり，本研究がそれを埋める」ことを示す**ことです．

### 4.2 テーマ別にグループ化する

- 「◯◯に関する研究は大きくアプローチA系とアプローチB系に分けられる」と整理します
- 各グループの到達点と限界を述べます
- 段落の最後で「これらに対し本研究は〜の点で異なる」と，**自研究との差分を必ず明示**します
- 各段落の主役は，先行研究ではなく「自分の研究との関係」です

### 4.3 先行研究を貶めない

Peyton Jonesは「他人の研究への謙虚さ（credit）はあなたの論文の価値を下げない．むしろ比較対象が優れているほど，それを超えるあなたの貢献が際立つ」という趣旨を述べています．査読者がその先行研究の著者本人である可能性も，現実的に高いと言えます．

### 4.4 章の位置：Widomの判断基準

| 位置 | 選ぶべき場合 |
|---|---|
| **冒頭**（イントロ末尾の小節 or 独立した2章） | 短くかつ十分詳細に書ける場合．または先行研究に対して早い段階で防御的な立場を明確にする必要がある場合 |
| **末尾**（結論の直前．"Discussion and Related Work" も可） | イントロや準備の章で手短に触れておける場合．または十分な比較に本文の技術的内容が必要な場合 |

Peyton Jones自身は「まず自分のアイデアを読者に届けよ」として末尾派です．投稿先の分野の慣習（トップ会議の採録論文を数本見る）に合わせるのが安全です．

## 5. 体裁と最終チェック（Widom）

- スペルチェックは必須です．言い訳は無用です
- 図表・グラフ・アルゴリズムはページ／カラムの**上部**に配置し，初出参照と同じページか次ページに置きます．図中のフォントサイズは，本文とほぼ同じにします
- 投稿前に**一度紙に印刷して見ましょう**（画面と印象が大きく違うことがあります）

## 6. 執筆プロセス

1. 完璧な文章を最初から書こうとしないでください
2. まずアウトライン（章 → 節 → 各段落のトピックセンテンス）を作り，running example（3.4節）を決めます
3. そこに肉付けし，後から磨きます（悪癖のチェックと無駄の削除は，推敲段階で行います．→[2-文書の書き方.md](2-文書の書き方.md)）
4. **早い段階から何度も他人のフィードバックをもらい**，すべてのコメントを改善の機会として真剣に聞きましょう（Peyton Jones）

## 7. 参考サイト・資料

- **Simon Peyton Jones, "How to Write a Great Research Paper"**
  CS論文執筆の最も有名な講義です．7つの具体的な提言がスライドと動画で公開されています．スライドの日本語訳も，同ページからリンクされています．
  https://simon.peytonjones.org/great-research-paper/
- **Jennifer Widom, "Tips for Writing Technical Papers"（Stanford大学）**
  簡潔で具体的な定番ガイドです．イントロの5段落構成，**running example**，Related Workの位置の判断基準，実験・文法のチェックリストなど，本ガイドの各章に統合済みです．
  https://cs.stanford.edu/people/widom/paper-writing.html
- **『エリート的な文章の書き方』**
  日本語の段落構成と文の構造的悪癖を解説するサイトです．[2-文書の書き方.md](2-文書の書き方.md)に統合済みです．巻末の作文技術の参考書籍リストも有用です．
  http://disadvantaged.web.fc2.com/
- **Justin Zobel, *Writing for Computer Science* (Springer)**
  CS論文執筆の定番教科書です．文章術から実験の報告，数式・図表の書き方まで網羅しています．
- **Jason Eisner の執筆アドバイス集（Johns Hopkins大）**
  NLP/ML寄りですが，具体的で実践的です．
  https://www.cs.jhu.edu/~jason/advice/
- **Whitesides, "Whitesides' Group: Writing a Paper"**
  化学分野の短い論文ですが，「アウトラインから書く」方法論として分野を問わず読まれています（"Whitesides writing a paper" で検索するとPDFが見つかります）．
- **Wobbrock & Kientz, "Research Contributions in Human-Computer Interaction" (ACM Interactions, 2016)**
  HCI研究の貢献タイプ7分類を解説した論文です．CHI/CSCW/UIST/IUI投稿時の貢献のframingに有用です（→[3-国際会議論文の傾向と対策.md](3-国際会議論文の傾向と対策.md)）．
- **Purdue OWL (Online Writing Lab)**
  英語アカデミックライティング全般（文法，パラグラフ構成，引用スタイル）を扱っています．
  https://owl.purdue.edu/
- **投稿先の会議・ジャーナルの採録論文を3〜5本精読する**
  最良の教材です．章立て，Related Workの位置，Evaluationの粒度など，その分野の「暗黙の型」が一番よくわかります．
